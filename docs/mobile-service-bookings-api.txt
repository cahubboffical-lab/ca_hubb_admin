MOBILE API HANDOFF
MY SERVICE BOOKINGS

GENERAL

All service request submissions now require a valid Sanctum Bearer token. The backend always saves user_id from the authenticated token. The mobile application must never send user_id.

The following POST endpoints now require authentication:

POST /api/car-inspection-requests
POST /api/sell-for-me-requests
POST /api/car-registration-requests
POST /api/car-ownership-requests
POST /api/car-finance-requests
POST /api/auction-sheet-verification-requests

Required headers:

Authorization: Bearer USER_TOKEN
Accept: application/json


GET THE SIGNED-IN USER'S SERVICE BOOKINGS

Method:
GET

Endpoint:
/api/my-service-bookings

Authentication:
Required.

Optional query parameters:

page
Positive integer. Default: 1.

per_page
Integer from 1 to 50. Default: 15.

type
One of:
car_inspection
sell_for_me
car_registration
car_ownership_transfer
auction_sheet_verification
car_finance

status
One of:
pending
in_progress
canceled
completed

Example:

GET /api/my-service-bookings?page=1&per_page=15&status=pending

HTTP 200 OK

booking_key is globally unique across service request tables. Mobile should use booking_key as its list key instead of id because different service types can have the same numeric id.

schedule is populated for Car Inspection and Sell It For Me. It is null for services without a booked visit time.

details contains fields relevant to that service type. It never includes sensitive admin notes or a full CNIC.

Bookings are sorted newest first.


VALIDATION ERROR

HTTP 422 Unprocessable Entity

{
  "error": true,
  "message": "The given data was invalid.",
  "errors": {
    "type": ["The selected type is invalid."]
  }
}


UNAUTHENTICATED RESPONSE

HTTP 401 Unauthorized

The mobile application must redirect the user to sign in before submitting a service request or opening My Service Bookings.
