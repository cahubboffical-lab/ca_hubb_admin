# Mobile Service Packages API

This document is only for `service_packages`.

Use this handoff when building mobile flows for:

- `car_inspection`
- `sell_for_me`

## Overview

Service packages are managed from admin in one table:

- table: `service_packages`
- type field is used to separate package groups

Current supported types:

- `car_inspection`
- `sell_for_me`

## Endpoint

- Method: `GET`
- Endpoint: `/api/get-service-packages`
- Auth: not required

This endpoint is available for both guest and authenticated mobile users.

## Query Params

- `type` required
- allowed values:
  - `car_inspection`
  - `sell_for_me`

## Type Meanings

### `car_inspection`

Use this type when mobile app needs packages for car inspection services.

Example request:

```http
GET /api/get-service-packages?type=car_inspection
```

Expected response behavior:

- returns only rows from `service_packages` where `type = car_inspection`
- each row is a service package for car inspection

### `sell_for_me`

Use this type when mobile app needs packages for sell-for-me services.

Example request:

```http
GET /api/get-service-packages?type=sell_for_me
```

Expected response behavior:

- returns only rows from `service_packages` where `type = sell_for_me`
- each row is a service package for sell-for-me

## Validation Rules

Backend validates:

```txt
type is required
type must be one of: car_inspection, sell_for_me
```

If `type` is missing or invalid, API returns validation error.

Example invalid request:

```http
GET /api/get-service-packages
```

Example invalid request:

```http
GET /api/get-service-packages?type=inspection
```

## Response Envelope

Success response format:

```json
{
  "error": false,
  "message": "Data Fetched Successfully",
  "data": [],
  "code": 200
}
```

Validation error format:

```json
{
  "error": true,
  "message": "The selected type is invalid.",
  "data": null,
  "code": 422
}
```

## Returned Fields

Each package object contains:

- `id`
- `name`
- `features`
- `icon`
- `price`
- `type`
- `type_label`
- `created_at`
- `updated_at`
- `created_by`
- `updated_by`
- `created_by_name`
- `updated_by_name`

## Field Details

### `id`

Database ID of the service package.

### `name`

Display name of the service package.

Example:

```json
"name": "Basic Inspection"
```

### `features`

Array of strings.

This should be rendered in mobile as a feature list / bullet list.

Example:

```json
["Exterior check", "Engine check", "Diagnostic report"]
```

### `icon`

Full public URL of the uploaded icon image.

Example:

```json
"icon": "https://your-domain.com/storage/service-packages/basic-inspection.png"
```

Can be `null` if no icon exists.

### `price`

Package price as stringified decimal.

Example:

```json
"price": "2500.00"
```

### `type`

Raw backend type.

Possible values for now:

- `car_inspection`
- `sell_for_me`

### `type_label`

Human-readable type label generated by backend.

Current mappings:

- `car_inspection` => `Car Inspection`
- `sell_for_me` => `Sell for Me`

### `created_at`

Creation timestamp.

Example:

```json
"created_at": "2026-06-25 11:22:33"
```

### `updated_at`

Last update timestamp.

Example:

```json
"updated_at": "2026-06-25 11:22:33"
```

### `created_by`

User ID of admin who created this package.

### `updated_by`

User ID of admin who last updated this package.

Can be `null`.

### `created_by_name`

Admin name who created the package.

Can be `null` if relation is missing.

### `updated_by_name`

Admin name who last updated the package.

Can be `null` if relation is missing.

## Mobile Integration Notes

- Call the endpoint separately for each type.
- Do not hardcode one mixed package list unless product wants both groups merged in UI.
- Render `features` as ordered or unordered list cards.
- Use `type_label` for headings if needed.
- Use `type` for app logic and filtering.
- `price` currently comes as string, so parse carefully in mobile if numeric operations are needed.
- `icon` is already a full URL from backend.

## Recommended Client Model

```ts
type ServicePackageType = 'car_inspection' | 'sell_for_me';

type ServicePackage = {
  id: number;
  name: string;
  features: string[];
  icon: string | null;
  price: string;
  type: ServicePackageType;
  type_label: string;
  created_at: string | null;
  updated_at: string | null;
  created_by: number;
  updated_by: number | null;
  created_by_name: string | null;
  updated_by_name: string | null;
};
```
