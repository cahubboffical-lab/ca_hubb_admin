CAR REGISTRATION AND CAR OWNERSHIP TRANSFER API DOCUMENTATION

BASE URL

Use the same API base URL as the rest of the CA Hubb mobile application.

Example production format:
https://your-domain.com/api

AUTHENTICATION

Authentication is optional for both endpoints. A guest can submit a request without a token. When the user is signed in, send the existing Bearer token so the request can be connected to that user account.

CONTENT TYPE

Send multipart/form-data or application/json. Do not send a package ID or price. These services do not use packages or prices.

AVAILABLE ENDPOINTS

1. Submit a car registration request

Method: POST
Path: /car-registration-requests

2. Submit a car ownership transfer request

Method: POST
Path: /car-ownership-requests

Both endpoints accept the same request fields and return the same response structure. They save data in separate database tables and create completely separate admin requests.

REQUEST FIELDS

full_name
Required string. Maximum 150 characters.

phone_number
Required string. Maximum 30 characters. Digits, spaces, parentheses, hyphens, and an optional leading plus sign are accepted.

is_filer
Required boolean. Send 1 for filer and 0 for non-filer. JSON true and false are also accepted.

car_model_id
Required integer. Must be a valid ID returned by the existing car models API.

model_year
Required integer. Minimum 1990. Maximum is the current year.

car_variant
Required string. Maximum 150 characters.

registration_place
Required string. It must be exactly one of these values:
Punjab
KPK
Sindh
Balochistan
AJK

EXAMPLE REQUEST

POST /api/car-registration-requests

full_name: Hamza Ali
phone_number: +92 300 1234567
is_filer: 1
car_model_id: 12
model_year: 2022
car_variant: GLi Automatic
registration_place: Punjab

For ownership transfer, send the same fields to:
POST /api/car-ownership-requests

SUCCESS RESPONSE FOR A NEW REQUEST

HTTP status: 201 Created

{
  "error": false,
  "message": "Car registration request submitted successfully.",
  "data": {
    "id": 15,
    "full_name": "Hamza Ali",
    "phone_number": "+92 300 1234567",
    "is_filer": true,
    "car_model_id": 12,
    "model_year": 2022,
    "car_variant": "GLi Automatic",
    "registration_place": "Punjab",
    "status": "pending",
    "created_at": "2026-07-18T12:30:00+05:00"
  }
}

The ownership endpoint returns the message:
Car ownership request submitted successfully.

DUPLICATE ACTIVE REQUEST BEHAVIOR

The backend prevents duplicate active requests separately for each service. A request is considered a duplicate when all of these values match an existing Pending or In Process request in the same service:

Normalized phone number
Car model ID
Model year
Registration place

If a duplicate is found, no new row is created. The existing request is returned with HTTP status 200 OK.

{
  "error": false,
  "message": "An active request already exists with the same phone number and vehicle details.",
  "data": {
    "id": 15,
    "full_name": "Hamza Ali",
    "phone_number": "+92 300 1234567",
    "is_filer": true,
    "car_model_id": 12,
    "model_year": 2022,
    "car_variant": "GLi Automatic",
    "registration_place": "Punjab",
    "status": "pending",
    "created_at": "2026-07-18T12:30:00+05:00"
  }
}

A new request can be submitted after the previous matching request is Completed.

VALIDATION ERROR RESPONSE

HTTP status: 422 Unprocessable Entity

{
  "error": true,
  "message": "The given data was invalid.",
  "errors": {
    "full_name": ["The full name field is required."],
    "phone_number": ["The phone number field is required."],
    "is_filer": ["Please select filer status."],
    "car_model_id": ["The car model id field is required."],
    "model_year": ["The model year field is required."],
    "car_variant": ["The car variant field is required."],
    "registration_place": ["The registration place field is required."]
  }
}

SERVER ERROR RESPONSE

HTTP status: 500 Internal Server Error

{
  "error": true,
  "message": "Unable to submit the car registration request. Please try again."
}

The ownership endpoint returns the corresponding car ownership error message.

MOBILE APP HANDLING NOTES

Treat both HTTP 200 and HTTP 201 as successful submissions.

Show the message returned by the API. HTTP 200 means the user already has the same active request, while HTTP 201 means a new request was created.

Display field messages from the errors object for HTTP 422 responses.

The initial status is always pending. Admin staff can move it to in_progress and then completed.

Keep the registration and ownership submission calls separate in the mobile code even though their form fields are identical.
